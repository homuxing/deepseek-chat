# 云端导入与多设备同步

## 使用目标

兼容 DeepSeek 导出的历史会话 ZIP，导入全部会话、消息分支和包内附件。成功后，同一账号在其他设备可以读取最新历史。

## 存储与导入

浏览器读取 ZIP 目录，统计对话数及按文件 ID 去重后的附件数，再逐条解压、校验和转换。小会话按最多 16 个且不超过 256 KiB 组成一批，通过 `POST /chats/imports/:id/chats` 保存；不超过 8 MiB 的附件直接 `PUT`，超过该大小的对象继续使用 multipart upload。ZIP 本身不上传给后端，Worker 不负责 ZIP 解压，导入流程不依赖高额 `cpu_ms` 配置。数据保存与对象上传最多四个任务并发，同一批次按真实存储结果计数。D1 保存会话目录、版本、附件引用和任务状态，R2 保存完整会话正文及附件原件。

导入使用独立的数据版本，附件在提交前独立暂存。共享原件逐个核对各引用路径，经大小、CRC 和完整内容指纹校验后只上传一次。所有条目校验和保存完成后，以同一事务发布附件并切换账号当前历史。失败、中断或账号变化时保留原有历史，停止新增任务，等待在途上传结束后清理未提交内容。结果响应丢失时确认已提交任务的结果，不重复上传。官方归档未包含原件的附件保留文件信息，不伪造原件。

导入绑定唯一任务 ID，文件、数据、权限、版本冲突及真实服务器错误如实报告，不完整内容不能提交为成功。实际容量仍受浏览器、Worker 和 Cloudflare 平台限制约束。

## 并发与同步

浏览器逐条读取和解压归档，按条目把会话或附件交给上传队列；会话批次与附件共用最多四个并发任务，小会话批量写入，大对象单独上传。共享附件保持统一 ID，首次读取后上传，后续副本仍进行大小、CRC 和完整内容指纹校验，全部校验通过后才能提交。

所有导入和编辑绑定发起账号及云端版本。其他设备更新后，旧版本写入明确失败，未保存内容保留供用户处理。多设备通过服务端推送获取更新通知；进入页面、重新显示页面和连接恢复时读取最新数据。离开页面或账号变化时清理连接及未完成读取，不进行固定轮询。

## 状态与验证

导入使用独立进度弹窗和进度蒙层，展示当前阶段、进度条及已完成/全部真实存储数量。浏览器读取 ZIP 目录后立即得到对话与去重附件总数，每项存储完成后更新已完成数量。提交阶段保留真实完成数量，直到完整结果确认后展示成功。

进行期间禁止关闭进度弹窗和设置窗口，并在刷新或关闭页面时提示确认离开；任务状态独立于设置组件保存。成功后自动更新历史，失败后展示具体原因并允许关闭。

验证完整导出包、超大单会话、分支和附件、共享副本、重复导入、空归档、并发保存、账号切换、网络中断、保存失败、取消与提交并发、超时清理及多设备进度隔离。新路径依赖 `migrations/0004_cloud_history.sql` 建立的目录、会话版本、附件及上传表；`migrations/0007_archive_import.sql` 的 `archive_mode` 字段与旧整包路径保留兼容。应应用全部迁移，避免环境之间出现表结构差异。提交事务复核完成状态及版本。方案不宣称完全免除 Cloudflare 限制，也不给出未经实测的倍数结论。
